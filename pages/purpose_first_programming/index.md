## 概要

この論文は著者Kathryn Cunninghamが博士論文としてミシガン大学に2021年に提出したものです。

この論文は大体3つの貢献をしています。

1. 初心者がコードトレースを避ける理由を、認知的困難と課題価値の低さの両方から説明したこと。
2. 会話型プログラマやエンドユーザ・プログラマにとって、領域特化型プログラミングぷろんを学ぶことが動機づけになりうると示したこと。
3. プログラミング教育設計において、認知負荷だけでなく、学習者の価値観・目標・自己認識も考慮する理論的視点を示したこと。

## 内容

2章では、プログラミング理解を整理するためのSBFフレームワークについて整理しています。

- structureは、コードの構文、文字列、関数、ループ、変数など。
- behaviorは、コードが実行されるときの動作、例えば、変数の値が変化することや、関数が呼び出されることなど。
- functionは、コードが達成する目的、例えば、ユーザーがボタンをクリックしたときに何が起こるか、平均を計算する、Webページから情報を取得する、データを整理する、など。

一般的なプログラミング教育理論が、structureからbehaviorを経てfunctionに至る、ということを重視している、と言っています。しかし、学習者によっては、functionからbehaviorを経てstructureに至る、という順序で学ぶほうが、自然であり、動機づけも高まり得ると言っています。読んでいる私としてもそう思います。先にfunctionがあってほしかったと思います。

3章では、主にコードトレース、要は人間インタプリタになってメモリの値を追跡するとか、実行を追跡するとか、それが難しく、面白くなく、カスである、ということを言っています。また、簡単なプログラミング言語、例えばscratchのようなやつは、目的を持った(例えば、UXをやっていたり、なんか生物の計算?わからないですけどそういうことととかをやっている)コンピューターサイエンス初学者にとっては、あまり価値が感じられない。ということでした。

4章では、コード・トレースを拒否することは、アイデンティティにも関わる、ということが言ってあります。

まあこういうところはどうでもよくてですね、良かったのは5章で提案されている目的第一プログラミング(Purpose-first Programming)です。

ここでは、題材としてbeautifulsoupを使ったwebスクレイピングが行われています。githubでよくあるパターンとか専門家にも確認して、一般的なやり方をレクチャーするようです。

1. まず、完成例を見せます。実在のwebサイトから、情報を取得するプログラムをみます。例として、ピザの店舗ページや選挙、動物愛護団体とかのページが使われています。ここから値段とか選挙の情報とか今週の迷子の動物の名前とかを引っ張ってくる、みたいなことを実際にやってみせます。

2. 次に、プラン単位でコードを見せます。完成プログラムは、

- URLを準備する
- webページを取得する
- htmlをsoupに変換する
- 特定のタグを集める
- タグからテキストやリンクを取り出す

というふうに分割されています。このコードの全体を見ます。このとき、ハイライトや説明によって、どこが1つのプランか、どこが変更可能か、ということが明示されます。
3. 次にプランごとの目標を並べます。これもさっきの順番と同じですが、これを見て、目的の分解を行う活動をやります。
4. 次にプランコードを並べます。目標ではなくて、実際のコードの断片です。ただし、完全に自由記述をするわけではありません。用意されたプランコードを、目的に合う順序に配置します。これは、parsons problem(混ぜられたコードを並べ替える問題)に近いですが、行単位ではなくて、プラン単位で扱うところが特徴です。
5. 最後に、プランの中の説明可能な部分、ここではスロットを埋めるということをします。例えば、

```python
url = "____"
tags = soup.find_all("____")
info = tag.get("____")
```

このとき、学習者は、文字列を入れるのではなくて、ここには取得対象のURLを、ここには探したいHTMlタグ名を、ここには取り出したい属性名を、というふうにwebスクレイピングの領域概念で考えます。
6. そして次にデバッグや説明課題が行います。間違いを含むプログラムを直したり、プログラム全体が何をしているかを説明したりします。重要なのは、この説明も、具体的な構文の話(ここのforループが...)じゃなくて、まずこのプログラムはどのような目的で、どのような分割の段階であるか、ということを説明する点です。

assemblingという用語が出てきますが、これは組み立てなので、複数のプランを組み合わせて作ることです。

またglass-box scaffoldingは、支援を与えるが、コードの複雑さは隠さないことです。これに対して内容を隠して、簡単な操作だけさせるのをblack-box scaffoldingと呼ぶそうです。

(具体的な実装をいつやるかということはやらないっぽいです?わからないですけど。まあ初学者ならいいんじゃないですかね。最後の説明課題が出来たなら、もっと細かい段階(subgoal)に分割して、自分でやれるようになってる気がします。この部分が、felleisenのhow to design programsのような感じですかね。)

## 動機づけ

中心的に扱っているのは、期待価値理論(expectancy-value theory)です。学習者は、

- その課題を達成できるかどうかの期待(expectancy)
- その課題を達成することの価値(value)

で動機づけが決まる、ということです。さらに、価値は、内発的な価値(面白いからやる)、達成価値(自分らしさと合うからやる)、有用価値(将来役に立つからやる)、低負荷(コストが低いからやる)などに分割されてます。

目的第一プログラミングは、プラン単位にすることで低負荷や実用的なwebスクレイピングにすることで有用価値を高めているという設計になっています。

## 文脈化されたプログラミング教育

プログラミング教育では、学習内容を現実的な文脈に置く(contextualized computing education)が有名らしいです(これは和訳してくれたAIがそう言っていた)。それの代表例として画像や音声などのメディアをやるということらしいです。あとはmatlabとかやる人はそう言うので。目的第一プログラミングもこの系統ですけど、文脈を与えるだけにとどまっていたところを、領域固有のパターンをプラントして明示的に与えることで、アシストしているのが違いです。
